# Assessment 2 Evidence Checklist

This file is a working checklist for evidence collection. Screenshots are stored outside the repository for the final submission.

| Evidence | Status | Suggested screenshot |
| --- | --- | --- |
| Feature branch separate from `main` | Complete | Branch page showing `feature/zhihe-zhang` ahead of `main` |
| Meaningful commit history | Complete | Commit history after documentation/final fixes |
| Working web application | Complete | Coordinator dashboard in the running application |
| Local automated tests | Complete | Terminal showing `pytest -q` and `10 passed` |
| GitHub Actions CI | Complete | Successful `tests` workflow run |
| Application configuration | Complete | `.env.example` and related configuration files |
| Deployment configuration | Complete | `docker-compose.yml` / `Dockerfile` |
| Configuration-management documentation | Complete | Files under `docs/` |
| Pull request to `main` | Pending | PR page before merge |
| Review/checks before merge | Pending | PR page showing successful checks/review |
| Final release/tag | Pending | GitHub release/tag page if created |

## Evidence notes

- Do not merge the development branch before capturing the pre-merge pull-request evidence.
- Commit history, configuration files and deployment files can be captured at the end because they remain available in GitHub.
- The branch-ahead view, pre-merge pull request and review state are process states and should be captured before they change.
